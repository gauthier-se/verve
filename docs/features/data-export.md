# Data export

- **Status:** Planned
- **Milestone:** M4
- **Related:** [Ingestion pipeline](ingestion-pipeline.md), [Accounts and administration](accounts-and-administration.md), [Notifications](notifications.md)

## Summary

Users can download their data at any time in open formats: CSV for spreadsheets and analysis, and JSON in the Verve native ingest format, which can be imported into another Verve instance. Workout routes are included as GPX. Data is never locked in.

## User stories

- As a user, I want my data in CSV to analyze it in a spreadsheet or a notebook.
- As a user, I want to move my data to another Verve instance.
- As a user, I want my workouts as GPX files.

## Scope

### In scope

- CSV and native JSON exports, GPX routes, account data (preferences, plans, dashboards).
- Filters by metric types and date range.
- Asynchronous generation and download.

### Out of scope

- Export to third-party services (Strava, Google Fit).
- Exports of other users' data by an admin.

## Functional requirements

- **FR-1**: Export formats:

  | Format | Content |
  |---|---|
  | CSV | One file per metric type (time, end time, value, unit, source, origin), one file for workouts, in a zip |
  | Native JSON | Samples, workouts and routes in format `verve.ingest.v1`, importable through the native ingest endpoint |
  | GPX | One file per workout with a route, included in both formats |
  | Account data | JSON with preferences, profile, source priorities, block rules, plans with check-ins, dashboards |

- **FR-2**: Filters: all data or selected metric types, optional date range, include or exclude workouts and account data.
- **FR-3**: Values are exported in canonical units by default, with an option to use the user's display units in CSV.
- **FR-4**: Exports are generated by a background job into `/data/exports`, then downloadable for 24 hours. The `export.ready` notification is emitted.
- **FR-5**: Only the owner can download an export. Download links require an authenticated session and are not guessable.
- **FR-6**: One running export per user at a time.
- **FR-7**: Native JSON exports can be imported with the CLI (`verve import native --user <name> <file>`) and through the native ingest endpoint, which makes them a migration path between instances.

## UX notes

- Export page in account settings with format, filters, estimated size, and a list of recent exports with download links and expiry.

## Data and API notes

- Endpoints: `POST /api/v1/exports`, `GET /api/v1/exports`, `GET /api/v1/exports/{id}/download`.

## Edge cases

- Very large exports: streamed into the zip without loading everything in memory.
- Disk space insufficient: export fails with a clear message.

## Acceptance criteria

- [ ] Exporting in native JSON then importing into an empty instance reproduces the same aggregates.
- [ ] CSV files open correctly in common spreadsheet tools (UTF-8 with header row).
- [ ] Expired exports are deleted from disk.

## Future ideas

- Scheduled exports to a folder for external processing.
